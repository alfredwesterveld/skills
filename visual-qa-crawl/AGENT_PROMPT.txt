```bash

BEAD_ID=$(echo "$BEAD_SUMMARY" | grep -o 'pg-[a-z0-9]*' | head -1)
```

## Execution Loop (per URL)

For each URL:

### 1. NAVIGATE
- Pop the first URL from queue
- Add to visited list
- Command: agent-browser open <base_domain><URL> && agent-browser wait --load networkidle

### 2. DESKTOP SCREENSHOT (1280×900)
- agent-browser set viewport 1280 900
- Scroll to trigger lazy-loaded images and StatCounter animation:
  agent-browser eval "window.scrollTo(0, document.body.scrollHeight)"
  then: agent-browser eval "window.scrollTo(0, 0)"
- agent-browser screenshot --full tmp/session-<timestamp>/visual-qa/<slug>-desktop.png
  (Derive slug from URL: replace / with -, strip leading/trailing dashes. E.g., / -> home, /en/system/ -> en-system)

### 2b. PROGRAMMATIC OVERFLOW SCAN (desktop)
agent-browser eval "JSON.stringify(Array.from(document.querySelectorAll('[class*=\"card\"], button, [role=\"button\"], nav a, td, th, h1, h2, h3, p, [data-badge]')).filter(el => { const r = el.getBoundingClientRect(); return r.width > 0 && el.scrollWidth > el.clientWidth + 1; }).map(el => ({ tag: el.tagName, cls: el.className.toString().slice(0, 50), text: el.textContent.trim().slice(0, 60), delta: el.scrollWidth - el.clientWidth })).slice(0, 10))"

Parse the JSON result. For each overflowing element, append to issues_log with description "<TAG> overflow: delta=+<delta>px text='<text>'":
- delta > 10px → severity: "High"
- delta > 2px → severity: "Medium"
- else → severity: "Low"

### 3. LINK EXTRACTION (once per URL, desktop pass only)

- Parse the JSON array of links
- Filter:
  * Must include base_domain
  * Must NOT be in visited list
  * Must NOT already be in queue

### 5. VISION ANALYSIS
Inspect BOTH screenshots (desktop and mobile) using your vision capabilities.

**Desktop checklist:**
- Text clipping or overflow outside containers/buttons
- Elements overlapping unintentionally
- Content bleeding off right edge at 1280px: check cards, badge numbers, file-type labels, action icons, and download counts are not partially clipped at the right edge
- Contrast issues (unreadable text)
- Broken grid / layout shifts
- CTA buttons or key headings cut off

**Mobile checklist (additional to desktop checks):**
- Horizontal scrollbar visible (should be none)
- Hamburger / nav menu visible and not cut off at top
- Touch targets (buttons, links) not overlapping each other
- Text not too small to read (no sub-14px prose on mobile)
- Cards: check no content (badge numbers, file-type labels, action icons, download counts) is partially clipped at the right edge
- Text: look for words ending abruptly mid-character or replaced by ellipsis due to container overflow, especially inside card titles and body text
- Badges / pill labels: verify full label is readable, not cut at the right border
- Hero sections not broken by narrow viewport
- StatCounter numbers fully rendered (not stuck at 0)

**Error page detection:** If page title contains "404", "500", or "Error", log as High severity without waiting for vision analysis.

## Critical Implementation Notes

1. **State tracking:** Explicitly manage queue/visited/issues_log. Log your state at key moments so you don't loop or forget progress.

2. **URL normalization:** Always construct full URLs as `<base_domain><path>`. Never mix URL formats.

3. **Screenshot naming:** Use slug derived from URL path. Examples:
   - / -> home
   - /contact/ -> contact
   - /en/system/ -> en-system
   - /de/system-de/ -> de-system-de
   - /internal/typography -> internal-typography

4. **Scroll and wait:** After scrolling, do NOT assume content is visible immediately. The networkidle wait and scroll pattern gives content time to render. Then screenshot.

5. **Default page state:** Never interact with modals, forms, or toggles unless explicitly instructed. Capture the default render (all modals closed, forms empty, etc.).

6. **Link extraction timing:** Only extract links after the desktop pass (saves one eval per URL). Links are the same regardless of viewport.

7. **Error handling:** If a page fails to load (404, 500, etc.), the page title will show the error. Log it immediately as High severity and continue.

8. **Context is finite:** Compress issue descriptions into 1–2 sentences. Include the specific visual problem and location (e.g., "Button text overflows in hero CTA at 1280px").
